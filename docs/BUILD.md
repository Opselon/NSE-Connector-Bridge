# Build

## 1. Requirements

- Python 3.12 or 3.13 (3.14 is untested on dev machines with broken
  numpy/pip — use a clean 3.12/3.13). CI uses 3.13.
- Windows 10/11 x64 for the packaged exe (MT5 + the MetaTrader5
  wheel are Windows-only). Linux builds/runs the pure-Python parts
  (tests, mock server, OpenAPI export) but cannot run MT5 tests.
- Pinned dependencies: `requirements.txt` (runtime + build) and
  `requirements-dev.txt` (adds pytest, pytest-asyncio, ruff).
  `pyproject.toml` carries the same pins as the `[project]`
  dependencies.

## 2. Local development

```bash
py -3.13 -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt

# Lint + tests (the CI Linux gate, runnable on Linux too)
ruff check tests/ scripts/
python -m pytest tests/unit tests/integration -q

# Run the bridge (dev)
.venv/Scripts/python -m nse_bridge            # GUI on http://127.0.0.1:8788
.venv/Scripts/python -m nse_bridge --gui none # headless
.venv/Scripts/python -m nse_bridge --diagnostic  # diagnostic console mode

# Mock NSE server (CONTRACT v1) for integration tests / manual runs
.venv/Scripts/python scripts/mock_server.py   # WS :9099, REST :9098

# Re-export the OpenAPI schema from the registry (CI enforces freshness)
.venv/Scripts/python scripts/export_openapi.py docs/openapi.json
```

CLI flags (`nse_bridge/main.py`, `build_parser()`):
`--host` (default 127.0.0.1), `--port` (default 8788), `--gui
auto|webview|browser|none`, `--no-connect` (skip MT5 auto-connect at
boot), `--diagnostic` (diagnostic console mode — see §4).

## 3. The exe (`bridge.spec`)

PyInstaller single-file build, x64:

```bash
.venv/Scripts/python -m PyInstaller bridge.spec --noconfirm --clean
# → dist/NSE-MT5-Bridge.exe
```

Spec contents:

- **Entry:** `run_bridge.py` → `nse_bridge.main:main`.
- **`console=False`** — no console window in production. Diagnostics
  use `--diagnostic` (see §4).
- **Version metadata:** `version="version_info.txt"` — generated
  from `nse_bridge.BRIDGE_VERSION` by
  `scripts/write_version_info.py`. After every version bump, re-run
  the script; CI enforces freshness with `--check`.
- **Windows manifest:** `manifest="windows/NSE-MT5-Bridge.exe.manifest"`
  — also generated by `write_version_info.py`. `asInvoker` (no UAC
  prompt; the Bridge runs unprivileged), `dpiAware`, `longPathAware`,
  Windows 8.1/10 in `supportedOS`.
- **Icon:** none — the repo has no `.ico` asset, and no binary icon
  is fabricated. PyInstaller falls back to its default icon. This is
  an explicit gap (docs/RELEASE.md): supply a real `.ico` and add
  `icon="…"` to the spec.
- **Bundled data:** `nse_bridge/gui/static` (Control Center HTML).
  Hidden imports cover `MetaTrader5`, `numpy`, `pywebview`,
  `websockets`, `uvicorn`, `loguru`, `webview.platforms`.
  Excluded: `tkinter`, `matplotlib`, `pandas`, `pytest`.

Smoke-check a built exe (also a CI step — `--help` exits before any
server or GUI starts, so it is safe on a runner):

```bash
dist\NSE-MT5-Bridge.exe --help
```

## 4. Diagnostic mode (`--diagnostic`)

`NSE-MT5-Bridge.exe --diagnostic` (or `NSE_BRIDGE_DIAGNOSTIC_MODE=1`,
or `diagnostic_mode: true` in config.json) enables:

- DEBUG telemetry events (otherwise dropped silently;
  ARCHITECTURE-CONTRACT §8),
- DEBUG log level (only when the configured level is still the
  default `INFO` — an explicitly set level is respected),
- on a frozen Windows build, a console window allocated
  best-effort (`AllocConsole` via ctypes, win32 + frozen only;
  failures swallowed — diagnostic mode works with or without it).
  On Linux/dev runs the flag is a no-op for the console part (a
  console already exists).

The flag is unit-tested (`tests/unit/test_diagnostic_flag.py`:
parses, defaults off, combines with other flags).

## 5. Versioning

- Single source of truth: `BRIDGE_VERSION` in `nse_bridge/__init__.py`
  (currently `1.0.0`).
- `scripts/write_version_info.py` derives `version_info.txt`
  (VSVersionInfo: FileVersion/ProductVersion, CompanyName `Opselon`,
  ProductName `NSE MT5 Bridge`) and
  `windows/NSE-MT5-Bridge.exe.manifest` from it. Never hand-edit the
  generated files.
- Releases use semver tags: `v1.2.3` (stable), `v1.2.3-rc.1`
  (prerelease). See docs/RELEASE.md.
- `min_connector_version` in `releases/latest` is honored by the
  updater: a release requiring a newer connector than the running
  one is refused (`MIN_VERSION_NOT_SATISFIED`).

## 6. CI (`.github/workflows/build.yml`)

Three jobs, chained: `test-linux` → `build-windows` → `release`
(tags only).

| Job | Runs | Steps |
|---|---|---|
| `test-linux` | ubuntu-latest | `ruff check tests/ scripts/` · `write_version_info.py --check` · OpenAPI freshness (`export_openapi.py` + `diff`) · `pytest tests/unit tests/integration -q` · marker-count visibility |
| `build-windows` | windows-latest | same lint + same unit/mock-integration suites on Windows (proves Windows imports work) · `pyinstaller bridge.spec` · `dist/NSE-MT5-Bridge.exe --help` smoke check · upload artifact |
| `release` | windows-latest, tags `v*` only | download exe · `write_release_manifest.py` (SHA-256 + manifest) · attach exe + `.sha256` + manifest to the GitHub release (`prerelease` iff the tag contains `-`, generated notes) |

The real-MT5 e2e suite is NEVER run in CI: GitHub-hosted runners
have no MT5 terminal, and a required-MT5 test fails loudly without
one. E2E is manual, Windows-with-MT5-only (docs/RELEASE.md).

Triggers: push to `main` / `refactor/**`, tags `v*`, PRs to `main`,
manual dispatch.

## 7. Known build gaps

- **No icon** (see §3). Awaiting a real `.ico` asset.
- **ARM64 unsupported** (see docs/COMPATIBILITY.md): x64 only; no
  ARM64 build is published, and the unsupported path must produce a
  clear message, not a broken binary.
- **`ruff check .` is not the gate yet:** 15 pre-existing findings
  remain in `nse_bridge/engine`, `nse_bridge/mt5`,
  `nse_bridge/timeutil`, `nse_bridge/main.py` (see docs/RELEASE.md).
  The gate lints `tests/ scripts/`, which is clean. Cleaning the
  remaining 15 is tracked follow-up work, not a Phase 6 change.
- **The frozen exe itself is only proven by Windows CI.** This Linux
  VM cannot run PyInstaller against the Windows-only dependency set
  (MetaTrader5 wheel, pywebview backends); `bridge.spec` validity on
  Windows is proven by the `build-windows` job, not locally.
