# Release

## 1. Release process

1. Bump `BRIDGE_VERSION` in `nse_bridge/__init__.py`.
2. Re-run the generators (CI enforces both with `--check` / `diff`):
   ```bash
   python scripts/write_version_info.py
   python scripts/export_openapi.py docs/openapi.json
   ```
3. Run the Linux gate locally (or wait for CI on the PR):
   ```bash
   ruff check tests/ scripts/
   python -m pytest tests/unit tests/integration -q
   ```
4. Merge only after explicit user approval (branch protection /
   project rule: never merge without it). Tag the release from `main`:
   `v1.2.3` for stable, `v1.2.3-rc.1` for a prerelease.
5. CI's `release` job (tags only) builds the exe on Windows,
   checksums it, writes the manifest, and attaches all three files
   to the GitHub release with generated notes:
   - `NSE-MT5-Bridge.exe` (single-file, x64, `console=False`)
   - `NSE-MT5-Bridge.exe.sha256` (`"<sha256>  NSE-MT5-Bridge.exe"`)
   - `release-manifest.json`
     (`{name, version, tag, commit, platform: "windows-x64",
     files: [{name, sha256, size_bytes}]}`)
6. Verify a download before announcing it:
   ```powershell
   (Get-FileHash NSE-MT5-Bridge.exe -Algorithm SHA256).Hash
   # must equal the .sha256 sidecar and the manifest entry
   ```

Stable and prerelease are separate by tag name: any tag containing
`-` (e.g. `v1.2.3-rc.1`) is published as a prerelease; `v1.2.3` is
stable. The two are never mixed in one release. No release is ever
cut from an untested build — the `release` job needs
`build-windows`, which needs `test-linux`.

## 2. What a release contains

- The exe (version metadata + manifest embedded; see docs/BUILD.md §3).
- SHA-256 checksum + manifest, generated by
  `scripts/write_release_manifest.py` from the real built file —
  never hand-written, never invented.
- Release notes (auto-generated by GitHub from merged PRs).
- The updater authority is CONTRACT v1 §3.5 `releases/latest`
  (version, download_url, sha256, size_bytes, min_connector_version,
  Ed25519 signature, released_at); GitHub Releases remains the
  artifact host behind that endpoint.

## 5. Known gaps (explicit, not hidden)

1. **No icon.** No `.ico` asset exists in the repo. The exe ships
   with PyInstaller's default icon until a real one is supplied.
2. **Release-signing public key missing.** `NSE_BRIDGE_UPDATE_PUBLIC_KEY`
   is unprovisioned and no bundled `update_public_key.b64` exists.
   The updater checks but can never install until the operator
   provisions the NSE release-signing public key. Fail-closed by
   design — do not work around it.
3. **Telemetry delivery gap** (CONTRACT v1 §4.2): no diagnostics
   upload endpoint. The local pipeline is complete; the sink is
   inert (`NullDiagnosticsSink`). ERROR/WARN events queue locally
   (128 items, 1 h TTL) and age out if no endpoint ever appears.
   Platform-side dependency — docs/PLATFORM-GAPS.md §2.
4. **`modify_pending` capability gate closed** (§17.4): live proof at
   market open + published minimum `connector_version` still owed.
   Until then the op is rejected as `UnsupportedOperation`.
5. **ARM64 unsupported.** x64 only; see docs/COMPATIBILITY.md.
6. **15 pre-existing ruff findings** outside the gated scope
   (`ruff check .`, ruff 0.17.5): 5× BLE001 blind `except Exception`
   (`engine/diagnostics.py` ×2, `main.py` ×1, `mt5/types.py` ×2),
   3× F401 unused imports (`engine/market.py` ×2,
   `engine/registry.py` ×1), 1× F841 unused local
   (`engine/risk.py`), 1× FURB162 (`timeutil.py`), 1× I001
   (`engine/__init__.py`), 1× PIE794 duplicate class field
   (`mt5/types.py`), 1× RUF022 unsorted `__all__`
   (`mt5/__init__.py`), 1× S110 try-except-pass (`mt5/types.py`),
   1× UP035 (`engine/registry.py`). Pre-existing in other phases'
   code; Phase 6 removed 9 findings (conftest swallow, export
   script, e2e dead assignments, import sorting in tests). Cleaning
   the remaining 15 is tracked follow-up work — not a Phase 6 change,
   and not a reason to widen the lint gate before it is clean.
7. **Windows CI not yet executed** on this branch; the frozen exe has
   never been built from this ref. First green `build-windows` run
   is required before any tag.
8. **Live Platform unverified** (see §3). No release should be
   announced as "verified against the live Platform" until the
   Platform side deploys the contract (PR #107) and a live
   enrolment/sync/command round-trip is observed.
9. **Backtest intentionally excluded** (clarification #2). There is
   no backtest subsystem, screen, or status — by design, not by
   omission. Do not add one in this phase.
